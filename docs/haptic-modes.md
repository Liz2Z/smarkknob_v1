# 旋钮手感模式

入口：板子当前地址 `http://192.168.0.103/#knob`。页面和控制服务都在 ESP32-C3 上，不需要电脑代理。DHCP 地址可能变化。

这是基于 AS5600 角度换相的电压模式手感控制，没有绕组电流反馈。参考 [SmartKnob](https://github.com/scottbez1/smartknob) 的段落中心、切档迟滞、死区和快速旋转卸力思路，使用本项目独立的 Rust 实现；未直接移植其 SimpleFOC/FreeRTOS 固件。

## 当前实现与验证边界

当前板端为 1,137,936 字节的渐进起力、低速位置平滑/快速回弹响应版本，已校准，停机，保留用户 1V / 15°。无限段落先做 1.5 计数的速度不确定度跟踪；慢转滤波 2ms，当前或估计速度超过 3rad/s 后滤波 0.3ms、保持至少 20ms。其他模式仍 1.5ms。峰值不按档距或速度降额。62 项 Rust 控制测试、6 项页面测试、release 和默认 clippy 通过。低速位置施力另做 0.5ms 平滑，快速响应期间旁路；实测计数和换相路径不变。无限段落在 ±1rad/s 内不叠加速度阻尼（其他模式仍为 ±0.3rad/s），位置恢复力仍正常。起力曲线采用扣除死区后的渐进正弦混合，15° / 1V 时满峰值位于距中心 3.9°，峰值上限仍 1V。下面的修正经过和实机日志包含历史版本数值，以本节和文末最新结果为准。

上一版 1,137,408 字节固件已完成低力度校准及 1V / 15°、3 秒静止定时检查：无驱动故障、I²C 错误 0，结束自行停止。末段 256 点、339.47ms，实际 751.2Hz，角度变化一计数约 0.088°，估计速度与电压指令均为 0；最大间隔 2.816ms。记录 `.local/trace-adaptive-filter-rest.*`。这只证明上一版静止检查通过；当前版本的握持起拧及松手手感已获用户确认，见文末验收记录；此历史静止检查本身不作为该验收依据。

## 使用

1. 停止原来的开环转动测试，确认转子与编码器机械连接，转子可以自由转动。
2. 点击“低力度校准”。使用 0.6V，约 5 秒，扫描一个电周期约 51°机械角；初始对齐可能额外移动。校准期间松手。
3. 校准会测量传感器方向和电角零位，检查位移是否符合 7 极对电机（容差 ±15%）。失败会关闭输出并显示原因，成功也会自动停止。
4. 选择模式和力度，点击“应用手感”，然后“启用手感”。建议先使用 0.2–0.4V。
5. 默认体验 3 秒自动停止；想持续使用，选择“持续体验”。关闭网页、切后台或 Wi-Fi 断开不影响运行；手动停止、设定时长结束、驱动故障或采样不可用才会停止。

校准结果只存在 RAM，上电或重新烧录后需重新校准。应用手感会停机，切换模式不会自动产生力矩。

## 模式

| 模式 | API 值 | 默认间距 | 行为 |
|---|---|---|---|
| 自由旋转 | `free` | 不使用 | EN 关闭，仅采集角度，不施加电磁阻力；可不校准 |
| 无限段落 | `detents` | 15° | 双向连续段落、切档迟滞、中心死区 |
| 两档开关 | `switch` | 60° | 档位 0/1，两端软限位 |
| 五档选择 | `selector` | 30° | 档位 0–4，默认总行程 120°，两端软限位 |
| 回中弹簧 | `spring` | 不使用 | 启动位置为中心，偏转后产生回中力 |
| 正向棘轮 | `ratchet_forward` | 15° | 编码器数值增加方向逐格通过，反向产生较强阻力 |
| 反向棘轮 | `ratchet_reverse` | 15° | 编码器数值减小方向逐格通过，正向产生较强阻力 |

正反向以编码器读数方向为准，不保证对应某一观察面的顺时针。虚拟限位和棘轮可被克服；它们不是机械锁。

`strength` 是电压幅值上限，范围 0.1–1V，不是牛米或电流；`step_deg` 范围 5–90°。阻尼、死区及电压渐变在固件中计算。当前无温度采样，长期及带载温升未验证。

### 段落手感修正

用户反馈段落模糊、回弹或阻力方向奇怪后，发现原实现把每次有正负方向的反馈都限制为 4V/s：在 1V 力度下，从 -1V 到 +1V 需要 500ms，前 250ms 仍保留旧方向。这会拖慢切档反馈，尤其影响较快手拧。

现仅在启动和快速转动卸力后恢复时，用 150ms 加力包络；运行中力度符号跟随当前角度，不再经过慢速反向渐变。无限段落、开关和选择器改为平滑的周期势阱，越过中点后拉向下一档；档位计数保留 60% 间距的迟滞，但计数变化不再造成力度跳变。开关和选择器的范围外继续使用恢复力，避免软限位外出现额外档位。中心死区为间距的 2%，最多 0.3°，并至少保留两个编码器计数，边缘平滑过渡。棘轮允许方向的段落峰值从力度上限的 10% 提高为 40%，反向仍提供更强恢复力。

新增测试覆盖下一采样反向施力、启动柔和加力、双编码器方向的换相数学符号、周期段落连续性、范围外软限位和双向棘轮曲线。上述测试验证控制逻辑，不代表实际手感或真实力矩已完成测量。

本次修正版已通过 39 项 Rust 测试、带 Wi-Fi 和不带 Wi-Fi 构建的 clippy 检查，并重新烧录。经用户确认松手后完成实机校准：编码器方向 -1、I²C 错误 0、最大控制更新间隔 14.631ms，无驱动故障。校准完成自动停机，默认保留无限段落、0.4V、15°，没有自动启动体验。修正后的主观手感仍需用户转动确认。

### 档位附近弹跳的修正

用户进一步反馈“在一档附近来回抖或反复弹跳”，因此第一轮曲线修正不能视为手感已验收。后续增加了以下处理：

- 速度滤波从 20ms 缩短为 1.5ms；阻尼按刚度平方根缩放，不再是很小的 `0.01 × strength`。对低速量化噪声设死区，在接近中心且速度很小时避免导数噪声驱动。
- 历史版本曾按 `min(strength, step_deg / 30)` 隐式降低峰值。用户指出设置值与实际不一致后已彻底移除；当前峰值上限直接为 `strength`，与档距无关。
- 有力度模式的档位中心继续输出三相相同占空比，电压差和目标力矩为零，保留绕组/反电动势制动。原先中心反复禁用桥会失去该阻尼。自由模式、快速旋转卸力、停止和任何故障仍关闭 EN。
- 运行时临时设置 AS5600 的 CONF：SF=11、名义功耗、关闭芯片自动睡眠看门狗。使用读改写、读回验证，保留其他位；停止后恢复启动时读到的完整配置。没有写 BURN/OTP。滤波响应参考 [ams 原厂 AS5600 数据手册，寄存器与滤波章节（Mouser 镜像）](https://www.mouser.com/datasheet/2/588/AS5600_DS000365_5_00-1877365.pdf)：SF=11 对应约 0.286ms，默认 SF=00 约 2.2ms。API 的 `encoder.conf` 为最近成功读回的配置值，失败时为空。

加入了带绕组 L/R、反电动势、数据手册裸转子惯量、12 位量化、角度噪声、0.3–0.8ms 传感器/总线延迟、错相采样和周期性 3ms 控制间隔的近似模型。模拟 0.2/0.4/1V 和 5/15/60° 下，手移四分之一档后松手，检查最终偏差与末段摆动范围。它用于回归控制稳定性，不替代真实惯量、负载、温升和主观手感测试。42 项 Rust 测试、7 项页面测试，以及有/无 Wi-Fi 的 clippy 均通过。

## 板端 API

POST 使用 URL 表单，空体接口不要发送 `{}`。GET `/api/status` 新增 `haptic` 对象，报告模式、校准、阶段、档位、相对角度、电压指令及最后停机原因。

```sh
# 应用模式，先停止输出
curl -X POST http://192.168.0.103/api/haptic/config \
  -d 'mode=switch&strength=0.4&step_deg=60'
# 校准（约 5 秒，会产生缓慢运动，由板端自动完成）
curl -X POST http://192.168.0.103/api/haptic/calibrate
# 启用当前模式；duration_ms=0 为持续，最大 30000
curl -X POST http://192.168.0.103/api/haptic/start -d 'duration_ms=3000'
curl -X POST http://192.168.0.103/api/stop
```

启动一次即可由板端独立运行，无需保活。`duration_ms=0` 持续运行，其他值由板端计时停止。旧 `/api/keepalive` 仅兼容返回状态，不再续期或停机。可选 Python 本机代理支持同名接口，使用 JSON 格式。

## 采样和保护

- 弱磁告警仍展示；按用户要求，MD=1、状态不矛盾且样本新鲜时允许尝试手感。没有屏蔽通信错误，也不代表角度精度已经验证。
- 样本年龄必须小于 25ms。断线、采样过期、磁铁未检测到、矛盾状态会关闭输出。
- 手感控制和采集均以 1kHz 为目标，I²C 为 400kHz。采集优先级 30，手感主任务 30，停机/旧开环主任务 1，停机采集 0，独立 HTTP 任务 2。TCP、Wi-Fi 管理和 JSON 格式化只在 HTTP 任务执行，主任务通过单个有界命令/响应信箱交换快照，不等待网络完成。RTOS 同优先级时间片为 1ms。I²C 使用独立可抢占线程的短阻塞事务，避免原来 100µs 异步轮询的调度开销；超时恢复也只在采集线程。主任务每周期至少给其他任务保留 500µs 的睡眠窗口。停机采集为 10Hz，CPU 为 80MHz。实际频率以实测为准。
- 控制间隔超过 20ms、时长结束或驱动 nFT 拉低都会关闭输出。网页连接和 Wi-Fi 不作为运行条件。
- 初版用单样本 15rad/s 触发停机，容易把正常快速手拧当成异常。现改为瞬时速度超过 60rad/s 暂时卸力，模式继续运行、继续采集；保持至少 150ms，且滤波速度低于 20rad/s 后渐变恢复。校准期间的异常快速运动仍拒绝校准。
- 网页拒绝旧状态覆盖新控制指令，防止异步请求顺序覆盖最新操作结果。

核心测试覆盖双向校准、校准不动/丢样拒绝、弱磁接受条件、角度跨零连续、切档迟滞、限位、棘轮/弹簧力方向、幅值上限、脱离网页独立运行及调度停止，以及快速转动卸力/降速恢复。页面测试覆盖七种模式初始化、无自动启动、表单协议和旧请求竞态。

实机已完成 0.6V 校准，方向为 -1；约 5 秒内无 I²C 错误，最大控制间隔约 13ms。用户反馈不同模式能感觉到手感变化，同时指出初版速度保护导致频繁退出；上述卸力处理用于修复该问题。各模式的精确力矩、定位精度和长期温升没有测量。


最终修复版验收：36 项 Rust 控制/解析测试、7 项页面脚本测试、17 项 Python 后台/接线页测试通过；默认和无 Wi-Fi 模式 clippy 通过。已重新烧录并再次完成校准，校准期间 I²C 错误 0，最大控制间隔约 14.4ms。七个模式分别完成 0.2V 上限、1 秒会话的启动/结束测试，无故障或停机错误；静止条件下这些测试的电压指令峰值为 0，不代表各模式力矩性能已测量。另实测了无保活约 500ms 后停机，以及运行中应用新模式立即停机。重新读回板端页面，包含快速旋转卸力和旧请求竞态修复。自动验收结束时保持停机；随后读到用户已自行在网页启动回中弹簧、1V，因此未再覆盖其参数或停止该会话，代理没有自动恢复输出。浏览器自动化工具超时，未取得页面截图；资源回读和页面脚本测试已完成。

### 网络与控制任务隔离验收（仅自由模式，后续见文末）

前述 14ms 级停顿继续定位后，确认控制循环同步执行了 TCP 轮询和状态格式化：实测轮询约 6ms、普通格式化峰值约 6.4ms。改用 `motor-control/src/decimal.rs` 固定精度编码避免通用浮点转文本，再将网络、Wi-Fi 电源管理和全部状态编码移入 `motor_http/worker.rs` 的独立任务。控制端只构造带捕获时间的不可变快照；`as5600::Telemetry` 同时复制传感器状态，格式化时不持采样锁。状态 JSON 容量从 768 增至 1024 字节。

新增 HTTP 任务后原内存只剩约 2.8KB，并出现回包超时；普通堆从 48KiB 增至 64KiB，另保留原有 64KiB reclaimed 堆，实测空闲恢复至 19,120 字节。网络任务最终优先级 2，采集和控制 30；较高的网络优先级曾导致 SDK 发送等待，未保留。采集改为独立线程内的可抢占短阻塞读取，维持 1kHz 目标和原超时/错误退避。任意任务 panic 会锁存紧急停止，控制输出函数在短临界区检查锁存，避免其他任务重新开启 EN；HTTP 启动拒绝该状态。

当前最终固件大小 1,131,776 字节，已烧录到 MAC `a4:cb:8f:1f:6d:40` 的 C3，地址仍为 `192.168.0.103`。44 项 Rust 测试、7 项页面脚本测试和有/无 Wi-Fi 的 clippy 通过。
